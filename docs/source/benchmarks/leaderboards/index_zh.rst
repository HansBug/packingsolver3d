天梯与完整结果
==============

本页放着这项研究的全部数字：97 个 case、十一个参与者，都在同样的表里。每个基准四张表：\ **case 表**\ （每个实例是什么、目前最好的界是多少、界从哪来），\ **天梯**\ （一行一个参与者，按总计排序，一列一个 case），目标为利润时的\ **每 case 装入件数**\ ，以及每个参与者在每个 case 上的\ **用时**\ 。参与者名录和跨基准汇总放在最前。每个格子背后的规则见 :doc:`../protocol/index_zh`\ ；参与者的详细介绍见 :doc:`../participants/index_zh`\ ；图见 :doc:`../gallery/index_zh`\ 。

天梯怎么读
----------

* **第一列**\ 是参与者名字并链接到其项目。后缀"（放松旋转约束）"表示该参与者无法保持该基准的固定朝向、解的是放松后的问题；"（参照）"标记按自身预算运行、用于认证最优值的精确程序。
* **第二列**\ 是所有 case 的总计，决定行序：背包族是装入利润（越大越好），两个装箱族是箱数（越小越好）。有任何缺失或非法 case 的参与者记为 ``n/a`` 并排在最后。
* **第三列**\ 重复理论界总计并在括号里给出到它的差距：利润用百分比，箱数用箱数差。``0`` 表示每个 case 都达到了界。
* **第四列起**\ 是各个 case。数值后的 ``*`` 表示等于该 case 目前最好的界，即\ **已证明最优**\ ；只有解同一变体的参与者才能得到。``invalid`` 表示摆放没有通过独立几何校验。
* 第一行数据\ **理论界**\ 不是参与者：它列出每个 case 最好的界，来源见各基准的 case 表。没有任何参与者达到的界仍然只是界，不是已知最优。

Egeblad-Pisinger 三维背包，二十件
---------------------------------

**实例考验什么。** 一个容器，二十件利润等于体积加 200 的物品，固定朝向。比例 50 时容器容积是物品总体积的一半，选\ *哪些*\ 物品装进去和怎么摆同样重要：那个常数让十四件小物品比同体积的六件大物品更值钱，先用最大块填满容器的启发式即便装得很紧也会把利润留在桌上。比例 90 时容器容积是总体积的九成，几乎全部都应装得下，难点转到摆放本身。五个形状类别把几何从立方体（``C``\ ）变到近似立方体（``D``\ ）、扁盒（``F``\ ）、长盒（``L``\ ）和混合（``U``\ ）。

**Case。** 二十个最优值中十六个有证明：十三个来自 CP-SAT 参照，其 ``OPTIMAL`` 状态就是证明；六个来自 PackingSolver 自己的界与当前解相遇（其中三个同时也是 CP-SAT 证明）。其余四个 case 都是比例 90（``D-C-90``\ 、``D-R-90``\ 、``F-R-90``\ 、``L-C-90``\ ），两个程序都没能在预算内收口，理论界一行显示的是 PackingSolver 未收口的界。最后一列是 packingsolver3d 自己报告的状态和运行时间。

**解读。** packingsolver3d 在十六个已证明的 case 上全部达到最优，总计 42,650,877，比界总计低 3.4 个百分点；精确参照 CP-SAT 总计 42,808,814，低 3.0 个百分点，两者的全部差别来自一个 case ``D-R-90``\ ：CP-SAT 20 s 后的当前解（6,218,886）高于 PackingSolver 10 s 后的当前解（6,060,949），两者都未被证明。六个 case（``D-C-50``\ 、``F-C-50``\ 、``F-C-90``\ 、``F-R-50``\ 、``L-C-50``\ 、``U-C-50``\ ）上 PackingSolver 的对偶可行函数界收口，求解在一到五秒内以 ``optimal`` 结束；其他已证明的 case 上它拿着最优装法但界没收口，于是一直搜到 10 s 时限并报告 ``feasible`` -- 那里的证明来自 CP-SAT。三个贪心库共用一个算法，py3dbp 的枢轴点规则、加了重力步骤的 fork 和它的 Go 移植，在多数比例 50 的 case 上返回完全相同的装法；在自由旋转下它们的总计是 41,234,099（jerry800416）、40,933,828（py3dbp）和 39,480,331（gedex/bp3d），比固定姿态的界总计低 6.6 到 10.5 个百分点，并且各自在七到八个 case 上（几乎全是比例 90 或随机利润的 case）放松后的值超过了固定姿态的界：那是旋转自由度，不是更好的装法，它们的行因此没有星号。``D-C-90`` 上 jerry800416 放松后的 6,756,027 高于所有固定姿态的值；是否存在同样利润的固定姿态装法尚无结论。在保持朝向的参与者里，U-Nesting SA 最接近，低 15.6 个百分点、两个 case 证明最优；其后 GA、ExtremePoint、BRKGA 低 18 到 19 个百分点（ExtremePoint 命中五个最优，全在立方体或 ``U`` 类实例上，但在扁盒和长盒类别上崩掉）；BottomLeftFill 低 37.8 个百分点：分层构建把每个矮层上方的高度浪费掉，在背包问题里就意味着少装东西。立方体实例 ``C-C-50`` 是这个差别最清楚的一幅画，图集里画了它：每个贪心库装六个立方体得 1,265,340，最优装十四个得 1,388,961。

数字说明了什么、没说明什么
--------------------------

它们说明：在最优值已知或已证明的小型无约束实例上，PackingSolver ``box`` 的 anytime 搜索在十秒内达到最优的频率远高于贪心装载启发式和通过构造式放置器驱动的序列元启发式，它自己的界能认证其中相当一部分最优值，且差距恰好在装得最紧的地方最大；它们也说明了它的十秒在哪里不够用 -- 60 件和 90 件的第 9 类切割、未决的比例 90 背包 case、十六个 THPACK9 实例 -- 以及一个给两倍时间的精确 CP-SAT 模型在背包族上与它旗鼓相当。它们没有给这些库作为软件排名：贪心库毫秒级给出答案，其中几个能处理 ``box`` 不支持的重量、稳定性和堆叠；这里每个数字都是单机单次运行；而且 PackingSolver 在背包 case 上用了多线程，其他一切都是单线程。注意事项在 :doc:`../protocol/index_zh` 里逐条写明。
