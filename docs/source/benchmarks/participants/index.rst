packingsolver3d, that is PackingSolver ``box``
----------------------------------------------

`PackingSolver <https://github.com/fontanf/packingsolver>`__ by Florian Fontan is a C++ solver for two- and three-dimensional packing problems; this package compiles its ``box`` solver into a Python extension and calls it in process (see :doc:`../../explanations/architecture/index`). ``box`` is an anytime optimisation solver rather than a loading heuristic. Its core is a tree search on an insertion-based branching scheme -- each node is a partial packing, children insert one more item at a candidate position -- explored with the iterative beam search of the companion `treesearchsolver <https://github.com/fontanf/treesearchsolver>`__ library, whose beam widens until the time limit is hit or the tree is exhausted. Upper bounds come from dual feasible functions; when they meet the incumbent the run stops early with status ``OPTIMAL``, which is what happened on every 30-item class-9 replicate and on 31 of the 47 THPACK9 instances. For several bins ``box`` layers a portfolio on top of the single-bin search: sequential single knapsack, sequential value correction, column generation (with the HiGHS LP solver compiled in) and dichotomic search on the number of bins; every sub-algorithm can be switched off through :func:`packingsolver3d.box.solve`. The runs here used the defaults: anytime mode, all sub-algorithms, ``time_limit=10.0``, ``memory_limit=1024``.

py3dbp
------

`py3dbp <https://github.com/enzoruiz/3dbinpacking>`__ (Enzo Ruiz, PyPI ``py3dbp`` 1.1.2) is the most downloaded Python 3D packing library. It implements the pivot-point heuristic described by Dube and Kanavathy ("Optimizing three-dimensional bin packing through simulation"): items are sorted by volume, each item is tried at the pivot points generated by the corners of the items already placed, in each of the six orientations, and goes to the first pivot where it fits; bins are filled one after another. It has no objective function and no search, so its result is a single greedy pass. The tables use the better of two passes, largest-item-first and as-listed, with ``distribute_items=True`` so that leftovers move on to the next bin. It always rotates, hence "rotation relaxed" on the two fixed-pose families.

jerry800416/3D-bin-packing
--------------------------

`jerry800416/3D-bin-packing <https://github.com/jerry800416/3D-bin-packing>`__ is a fork of py3dbp that adds a fix-point step (after a pivot placement the item is dropped and pushed toward the origin until it rests on something), an optional stability check, load-bearing limits and corner placement, and comes with plotting utilities. The runs used ``fix_point=True`` and ``check_stable=False`` so that only geometry is enforced, with the same two item orders as py3dbp. Same pivot-point core, hence the same relaxed-rotation caveat.

gedex/bp3d
----------

`gedex/bp3d <https://github.com/gedex/bp3d>`__ is a Go port of the same pivot-point heuristic, derived from ``bom-d-van/binpacking`` and using ``float64`` dimensions. It cannot be asked to keep an orientation, so it is "rotation relaxed" where the variant fixes the pose. One greedy pass per case; on the knapsack family the profit is the sum over the items it placed in the single container.

U-Nesting
---------

`U-Nesting <https://github.com/iyulab/U-Nesting>`__ (iyulab, Rust, MIT) is a 2D nesting and 3D bin packing engine with a C FFI. Its 3D module offers five strategies that were run separately: **ExtremePoint** places items at the extreme points left by earlier items in the spirit of Crainic, Perboli and Tadei's constructive heuristic; **BottomLeftFill** is a layer-building bottom-left-fill greedy; **GA** and **BRKGA** evolve the item sequence, with a plain genetic algorithm and a biased random-key genetic algorithm respectively, decoding each sequence with the constructive placer; **SA** runs simulated annealing on the sequence. The library packs one container per call, so several bins were handled by repeated calls, each receiving the items left over from the previous container. The strategies honour the fixed pose and received the 10 s budget; on the THPACK9 family, where every rotation is allowed, four of them produced placements outside the container on seven to nine of the 47 instances, which the validator rejects.

OR-Tools CP-SAT exact model (reference)
---------------------------------------

`CP-SAT <https://developers.google.com/optimization/cp/cp_solver>`__ is the constraint-programming solver of Google `OR-Tools <https://github.com/google/or-tools>`__ (9.15 here). The reference is an exact model of the fixed-pose three-dimensional knapsack -- one optional interval per item and axis, pairwise non-overlap disjunctions, maximise profit -- run for 20 s on one thread with 4 GiB. When CP-SAT ends with status ``OPTIMAL`` the value is a proven optimum and enters the bound row; where it ends with a feasible solution only, its bound is loose and PackingSolver's bound is used instead. It certified thirteen of the twenty knapsack cases and, on one open case, holds a better incumbent than PackingSolver after 10 s.

Martello-Pisinger-Vigo 3dbpp.c (reference)
------------------------------------------

`3dbpp.c <http://hjemmesider.diku.dk/~pisinger/codes.html>`__ is the authors' branch-and-bound for the three-dimensional bin packing problem (Martello, Pisinger and Vigo, *Operations Research* 2000; general-packing variant with den Boef and Korst, *ACM TOMS* 2007). It combines lower bounds on the number of bins with an exact one-bin filling routine inside a branch-and-bound over bin assignments, and reports a lower and an upper bound when the time limit stops it. It was run for 1 s on one thread with the generator's default general-packing parameters on the thirty class-9 replicates it generated; its upper bound is shown in the table, its lower bound of three enters the bound row.
